# Shortcut: Mark (hub-and-spoke)

Apple does **not** support inline Siri parameters for Shortcuts-app shortcuts — you cannot say "Mark Food" and have "Food" passed as input to a shortcut named "Mark". The only way to get true one-phrase logging is to make the *whole phrase* a shortcut name. So this uses a hub-and-spoke design:

| Shortcut | Role | Siri phrase |
| --- | --- | --- |
| **Mark** (core) | Does the dictionary lookup + POST. Reads Shortcut Input if a wrapper passed one, else shows a menu. | "Mark" (then pick / speak) |
| **Mark Coffee** | Wrapper → runs Mark with input "Coffee" | "Mark Coffee" |
| **Mark Food** | Wrapper → runs Mark with input "Food" | "Mark Food" |
| **Mark Water** | Wrapper → runs Mark with input "Water" | "Mark Water" |
| **Mark Monk** | Wrapper → runs Mark with input "monk" (alias for nof) | "Mark Monk" |
| **Mark Chair** | Wrapper → runs Mark with input "chair" (alias for chairmaxxing) | "Mark Chair" |
| **Mark Custom** | Wrapper → runs Mark with input "Custom" (Mark then asks for the text) | "Mark Custom" |

Generated by `generate-log-event.py` → `mark.shortcut` + `mark-<event>.shortcut`.

---

## Core: Mark

```text
1. [If] Shortcut Input has any value
   → [Set Variable] → "label" = Shortcut Input    ← passed by a wrapper
   [Otherwise]
   → [List] Coffee, Food, Water, NoF, Chairmaxxing, Custom
   → [Choose from List] "What are you logging?"
   → [Set Variable] → "label"
   [End If]

2. [Dictionary]   ← both cases, so "food" and "Food" both resolve
   - Coffee/coffee       → caffeine
   - Food/food           → food
   - Water/water         → water
   - NoF/nof             → nof
   - Monk/monk           → nof            (alias used by "Mark Monk")
   - Chairmaxxing/...    → chairmaxxing
   - Chair/chair         → chairmaxxing   (alias used by "Mark Chair")
   - Custom/custom       → custom

3. [Get Dictionary Value]  key: [label]  → store as "event_type"

4. [Text] "" → [Set Variable] "custom_value"   ← initialise empty

5. [If] event_type = "custom"
   → [Ask for Input] Text "Describe the event"
   → [Set Variable] "custom_value"
   [End If]

6. [Device Details] Device Model → store as "source"

7. [Get Contents of URL]  POST, Content-Type: application/json
     {
       "event_type": [event_type],
       "value": "",
       "notes": [custom_value],
       "source": [source]
     }

8. [Speak Text] "Got it"
```

---

## Wrapper: Mark Coffee (and friends)

Each wrapper is three actions (this mirrors how the Shortcuts app builds it):

```text
1. [Text] "Coffee"                ← the label / alias to log
2. [Set Variable] "mark_input"    ← stores the Text output
3. [Run Shortcut]
   - Shortcut: Mark
   - Input: [mark_input]          ← becomes Shortcut Input inside Mark
```

The wrapper's *name* ("Mark Coffee") is what makes "Hey Siri, Mark Coffee" fire in one shot. "Run Shortcut" legitimately passes the label to the core — the supported way to pass input, unlike Siri inline.

**Aliases**: a wrapper can pass a short alias instead of the full label. "Mark Chair" passes `chair`, and the core dictionary maps `chair → chairmaxxing`. Add the alias to both the wrapper (the Text value) and the core's Dictionary.

---

## Siri experience

| You say | What happens |
| --- | --- |
| "Hey Siri, Mark Coffee" | One shot — logs `caffeine`, no prompts |
| "Hey Siri, Mark Monk" | One shot — logs `nof` (monk = alias) |
| "Hey Siri, Mark Chair" | One shot — logs `chairmaxxing` (chair = alias) |
| "Hey Siri, Mark Custom" | Runs core, asks "Describe the event", logs `custom` |
| "Hey Siri, Mark" | Core shows the menu / asks conversationally |

---

## Install order

1. Import **mark.shortcut** first (it asks for your Apps Script URL on import)
2. Import each **mark-\<event\>.shortcut** wrapper (they reference "Mark" by name)
3. Add the wrappers you use most to your Apple Watch / Home Screen

---

## Notes

- Adding a new event = add it to `LIST_ITEMS` + `EVENT_TYPE_MAP` in `generate-log-event.py`, rerun, and a new wrapper is generated automatically
- The dictionary's lowercase variants + the `event_type = "custom"` check make the core case-proof regardless of how Siri transcribes the spoken word
- If Siri struggles with "Chairmaxxing" (a coined word), the "Mark" → menu fallback always works
